# Fixed-Base residual A–E ablation

This experiment uses the original BF16 Qwen1.5-MoE-A2.7B-Chat routed expert
weights and the repository's packed exponent/mantissa Base. The Base is encoded
once from each original matrix and is copied unchanged into every case. Only
the residual representation changes. The older A/B/C labels in
`run_base_qjl_sweep.py` describe a different experiment.

| Case | Residual representation | Calibration/training |
| --- | --- | --- |
| A | zero | none |
| B | exact dense FP32 `W - Base` | none |
| C | existing Gaussian QJL packed signs and FP32 row norms | none |
| D | shared BF16 factors and BF16 expert codes | ResCode grouping statistics; covariance initialization only |
| E | packed asymmetric INT2 and FP16 row scale/offset | original routed activations for GPTQ Hessian |

Case D calls `rescode.merging.lowrank_init.compute_covariance_init` on **the
mantissa-Base residual**. It uses ResCode's frequency weights and `alpha=2.0`,
so inference multiplies `A diag(z) B` by 2.0. No ResCode output fitting,
gradient descent, or model merging is applied. It is labeled *ResCode-style
Low-rank (Initialization Only)*, not full ResCode.

Case E adapts the sequential Hessian error-feedback algorithm of the
[official GPTQ implementation](https://github.com/IST-DASLab/gptq) to the
residual matrix. Quantizer scale and offset are rounded to FP16 before the
error-feedback pass. The Hessian is formed from original expert inputs, with
diagonal damping. Four 2-bit codes are packed per byte. Inference currently
dequantizes into a temporary FP32 matrix and runs GEMM; there is no optimized
packed INT2 inference kernel. `latency.csv` separates decode and GEMM timings.
Latency uses held-out inputs for the same first expert ID in each layer by
default (`--latency-experts 1`), with warmup, synchronized repeats, wall time,
and CUDA event time. It is a measured sample, not a claim about full model
throughput. Case C's complete expert forward reuses the Gate/Up projection
through the existing fused path when the Triton conditions are met.

## Inputs and run commands

The default GPTQ calibration corpus is DCLM; the held-out diagnostic corpus
is Wikipedia. Missing default JSONL files are generated by the repository's
`prepare_calib_datasets.py`. The default ResCode grouping cache is
`results/qwen/calib_stats/dclm-n2400-seed42.pt`. Generate it first with
`bash scripts/QJL/run_residual_norm_ablation.sh` if it is missing. Original
Qwen safetensors are resolved from the local Hugging Face cache or downloaded.

Small real-model smoke test (no downstream evaluation or automatic shutdown):

```bash
LAYERS=0 MAX_EXPERTS=2 N_SENTENCES=8 GPTQ_CALIBRATION_SAMPLES=4 \
DIAGNOSTIC_SAMPLES=4 SKIP_EVAL=1 OUTPUT_DIR=results/residual_ablation_smoke \
AUTO_PUSH_AND_STOP=0 bash scripts/QJL/run_residual_ablation.sh
```

Full A–E sweep and the five default tasks:

```bash
CASES=A,B,C,D,E D_FACTORS=1,2,4 \
TASKS=arc_easy,arc_challenge,mmlu,openbookqa,rte \
bash scripts/QJL/run_residual_ablation.sh
```

`--mode compress` and `--mode eval` are also available through
`run_residual_ablation.py`. A partial layer or expert selection requires
`--skip-eval`. Set `MODEL_PATH`, `OUTPUT_DIR`, `GROUPING_CACHE`,
`GPTQ_CALIBRATION_PATH`, `DIAGNOSTIC_PATH`, and the sampling variables in the
wrapper to reuse local inputs. `--fp32-residual-device auto` places Case B's
dense FP32 residual on CPU when it cannot fit the GPU; this exact upper bound
can evaluate slowly on a single 48 GiB GPU.

## Outputs and resume behavior

`results/residual_ablation/` contains `summary.csv`,
`projection_errors.csv`, `memory_breakdown.csv`, `group_budgets.csv`,
`latency.csv`, `config.json`, and `REPORT.md`. Each variant (`A`, `B`,
`C_d1`, `C_d2`, `C_d4`, `D_d1`, `D_d2`, `D_d4`, `E`) has its own
`layer_<n>.pt` checkpoints, per-layer diagnostics, and optional
`eval_metrics.json`. Checkpoints contain only packed Base and the selected
residual representation; shared D factors are serialized once per group.

Resume validates the variant configuration digest, the SHA-256 hash of the
original BF16 layer weights, and the saved checkpoint size before reusing a
layer. Stored tensor bytes and serialized checkpoint bytes are reported
separately. Group-level QJL budget, rank, actual BF16 factor/code bytes, and
utilization are in `group_budgets.csv`; serialized metadata overhead is in
`memory_breakdown.csv`. Only C at `D=2n` is nominally storage matched to E.

## Automatic GitHub push and instance stop

The full wrapper calls `push_results_and_shutdown.sh` **only after** every
requested evaluation has completed and the result files contain accuracy.
The separate script stages `.csv`, `.json`, `.md`, and `.txt` result files
below `results/residual_ablation/`, commits and pushes them to `ablation`,
verifies the remote commit, then calls Vast's `stop instance`. Large `.pt`
checkpoints and the activation cache are excluded from GitHub's regular Git
push. If the push, verification, credentials, or stop command fails, the
instance remains running. `AUTO_PUSH_AND_STOP=0` disables this step.

The smoke command uses `OUTPUT_DIR=results/residual_ablation_smoke` and cannot
trigger automatic stop. The full run does not start during installation or
tests; run the full command explicitly when ready.
